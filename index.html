SECTION03OF 13Problem Statement
03 · Problem Statement
--

Problem Statement

Comparing flights means weighing several factors at once, and the details are easy to lose track of:

  • Price, airline, times, duration and stops all matter, but they are rarely easy to view together for different options.
  • Prices and availability change, so travellers need to know when a result was fetched and which currency it is shown in.
  • Travellers need a clear route to the airline or booking provider once they have decided.
  • Real-world data is messy: results can be incomplete, slow, or unavailable, and the experience must stay usable anyway.
SECTION04OF 13Proposed Solution
04 · Proposed Solution
--

Proposed Solution

Anga360 pulls flight data from the SerpApi Google Flights API through its own FastAPI backend, normalises it, and presents it in a responsive React interface.

🔍

Search

One-way and round-trip search with airport lookup, validation, passengers and cabin class.

⚖️

Compare

Sort, filter, and compare up to three flights side by side on price, duration, stops and more.

🎫

Continue

Follow the provider link to the airline or booking site. Anga360 never sells tickets or takes payment.

SECTION05OF 13Objectives
05 · Objectives
--

Objectives

  • Deliver flight search, results, filtering, sorting and side-by-side comparison without requiring an account.
  • Show every price with its currency, the time the search ran, and a notice that prices and availability may change.
  • Keep the SerpApi key on the server: the browser only ever talks to the FastAPI backend.
  • Survive external API and network failures with a clear message for each case.
  • Stay usable and accessible at 360 px, 768 px and 1280 px, with the main flow working by keyboard.
  • Finish every Must-have item before any Should-have or Could-have item.

SECTION08OF 13System Architecture
08 · System Architecture
--

System Architecture

LayerTechnologyResponsibilities
PresentationReactSearch form, results, sort/filter, comparison, account pages if built
ApplicationFastAPI (Python)Validates requests, calls SerpApi, normalises results, handles errors, accounts and saved flights
DataPostgreSQLAccounts, saved flights, search history. Live flight results are not stored permanently

The browser never talks to SerpApi, which keeps SERPAPI_API_KEY on the server. Provider responses are normalised into one format so the frontend is not coupled to raw provider fields. Identical searches are cached for about 10 minutes and requests are rate-limited to protect quota.

SECTION10OF 13Plan & Risks
10 · Plan & Risks
--

Plan & Risks

  1. Planning (wk 1): agree MVP, review SerpApi docs, set up GitHub, make one real API call.
  2. Design (wks 1–2): wireframes, colours and branding, user journey.
  3. Backend (wks 2–4): FastAPI, PostgreSQL models, SerpApi integration, validation.
  4. Frontend (wks 3–5): React components, results, sorting, filtering, comparison.
  5. Integration (wks 5–6): connect both ends; accounts and saved flights if time allows.
  6. Testing & launch (wks 6–7): Pytest, Postman, acceptance tests, deployment, presentation.
TOP RISKS

SerpApi quota running out (cache, rate-limit, monitor) · slow or changing API responses (timeouts, defensive normalising) · leaked secrets (git-ignored .env) · scope growth (Must-haves first).

SECTION11OF 13Open Decisions
11 · Open Decisions

Open Decisions

To be agreed before the requirements are final:

  • Airport lookup data source, and which display currencies the MVP supports (and SerpApi can return).
  • Whether guest searches are stored, plus password rules and token expiry.
  • Whether accounts and saved flights fit the capstone timeline.
  • Hosting for FastAPI and PostgreSQL (does Vercel support the Python backend?).
  • CSS or Tailwind CSS, accessibility checks in testing, and whether the SerpApi quota is enough.
  • Who owns updates to requirements, database design and API documentation.
SECTION12OF 13Conclusion
12 · Conclusion
--

Conclusion

Anga360 is a focused web app that: reliable flight search, clear results and honest comparison, with prices always shown alongside their currency and the time they were fetched.

It deliberately stops at the provider link. Tickets, payments and reservations stay with the airlines and booking providers, which keeps the scope realistic for a seven-week capstone.
